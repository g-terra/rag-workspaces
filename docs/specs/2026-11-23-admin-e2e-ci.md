# Run the admin UI's Playwright tests in CI on the smoke stack

## Summary

`pnpm e2e` starts the throwaway smoke stack, runs the admin UI's Playwright tests against it and
removes the stack again, also when a test fails. A new GitHub Actions workflow, `E2E`, runs it on pull
requests that touch the admin UI or the stack under it, nightly on `main` and on demand. Until now the
tests only ran by hand against a developer's own stack.

## Why

The owner chose (2026-11-22, admin UI thread) to run the admin UI's Playwright tests against the real
stack, locally and in CI, with CI reusing the smoke stack from `2026-11-22-compose-smoke-test.md`
(#34) once it landed. Work breakdown Workstream 3 item 10 (`docs/work-breakdown.md`) plans Playwright
e2e for login, upload and the playground once M4 lands. The tests themselves came with the admin UI
specs (`2026-11-22-admin-sign-in.md` to `2026-11-22-admin-library.md`).

## Design

1. `scripts/smoke/e2e.ts` (root script `pnpm e2e`), shaped like `scripts/smoke/run.ts`:
   - `up()` from `scripts/smoke/stack.ts` builds and starts the stack, writing a fresh `.env.smoke`
     when none is running;
   - runs `pnpm --filter @rag/admin e2e` with `E2E_BASE_URL` set to the smoke admin UI
     (`ADMIN_UI_URL`, `http://localhost:18080`) and `E2E_USERNAME` / `E2E_PASSWORD` from the seeded
     admin in `.env.smoke`. The password goes to the child process's environment only, never onto a
     command line. A failed test's Playwright trace does record what was typed into the Keycloak form,
     including that password; it is generated per run and the stack is removed afterwards, so the
     uploaded trace holds nothing that still works;
   - other arguments go to Playwright (`pnpm e2e upload.spec.ts`); `--keep` leaves the stack running;
   - on a failure it prints every service's state and recent logs (`logs()`), then `down()`.
2. `.github/workflows/e2e.yml`: installs dependencies and Playwright's Chromium (with its system
   packages), runs `pnpm e2e`, and on failure uploads `apps/admin/playwright-report/` and
   `apps/admin/test-results/` (traces of failed tests) as the `playwright-report` artifact for 7 days.
   Paths are the smoke workflow's plus `apps/admin/**`. The nightly run is at 03:30 UTC, half an hour
   after the smoke test, so the two don't build at once.

The Playwright config needed no change: it already reads `E2E_BASE_URL`, retries once and uses the
`github` reporter when `CI` is set.

## Decisions and trade-offs

| Decision | Alternatives considered | Why this one |
| --- | --- | --- |
| A separate `E2E` workflow | A second job in `smoke.yml`; a step after the smoke checks | Runs on admin-only changes (which the smoke test skips), fails on its own line in the PR checks, and each job keeps its own stack |
| A script that wraps up, test, down | Inline steps in the workflow reading `.env.smoke` | The same command works locally (`pnpm e2e`), and tear-down happens even when Playwright fails |
| Only on PRs that touch the UI or the stack | On every PR | The stack build and Langflow start take minutes; docs-only PRs don't need it |
| Credentials through the child's environment | Writing them to `$GITHUB_ENV` | Nothing secret leaves the script; `.env.smoke` is generated per run anyway |

## Interfaces and contracts

- **HTTP API**: None.
- **Configuration**: None new. The script sets `E2E_BASE_URL`, `E2E_USERNAME` and `E2E_PASSWORD`, which
  `apps/admin/playwright.config.ts` and `apps/admin/e2e/sign-in.ts` already read.
- **Data**: None. The stack's volumes are removed after each run.
- **Langflow**: None.
- **Events and logs**: None.

## Operations

Locally it needs Docker and Chromium (`pnpm --filter @rag/admin exec playwright install chromium`,
once). It uses the smoke stack's ports (13000, 18080, 18081, 17860, 18000), so it can't run at the same
time as `pnpm smoke`; a dev stack on the normal ports is untouched. If a run is interrupted, remove the
stack with `node scripts/smoke/stack.ts down`.

## Testing

The workflow itself is the test: the `E2E` check on this PR runs `pnpm e2e` on GitHub. Checked by hand
in a cloud sandbox: the smoke stack came up healthy with the admin UI on 18080 and Keycloak on 18081, and
all 11 Playwright tests passed against it with the credentials from `.env.smoke` and `CI` set. The
sandbox's proxy can't build images, so there the images were built separately and the stack started
without `--build`; the script's own up, test and down sequence is checked by CI.

## Out of scope and follow-ups

- Playground and chat tests come with M4 step 2.
