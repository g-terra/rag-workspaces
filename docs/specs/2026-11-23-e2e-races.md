# Wait for stored replies and dialog focus in the e2e tests

## Summary

Three Playwright tests read state before it was ready. They passed on GitHub's hosted runners and failed
on a faster machine. The tests now wait for that state. No product code changes.

## Why

On 2026-11-23, CI ran briefly on Guilherme's own Mac while hosted runners were blocked. These tests
failed there:

- `conversations.spec.ts` (flaky): it read the stored conversation and found only `user, assistant,
  user`.
- `workspaces.spec.ts` (failed twice): the create dialog stayed open after Escape.

## Design

- `apps/admin/e2e/conversations.spec.ts` and `apps/admin/e2e/playground.spec.ts`: a reply's text is on
  screen before the API has finished storing it, so the tests poll `GET .../conversations/{id}` until
  the four messages are there.
- `apps/admin/e2e/workspaces.spec.ts`: before pressing Escape, the test waits until focus is inside the
  create dialog. Opening the dialog from the switcher's menu moves focus a moment after the dialog
  appears.

## Decisions and trade-offs

| Decision | Alternatives considered | Why this one |
| -------- | ----------------------- | ------------ |
| Poll the API in the test | Have the stream's `done` event wait for the write | The UI doesn't need the row stored before showing the reply. Only the test asserts on storage |
| Wait for focus, then press Escape | Click the dialog's Close button | The test checks that keyboard Escape returns focus to the switcher, so it must keep using the keyboard |
