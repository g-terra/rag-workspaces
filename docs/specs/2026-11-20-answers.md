# Answers with citations, token usage and feedback

## Summary

`POST /v1/workspaces/{slug}/answers` answers a question from the workspace's material, with numbered
citations, the model used, token usage and latency. Every answer is stored, failures included, and the
asker can rate it. When nothing relevant is found the API returns a fixed "couldn't find anything" answer
without calling the model.

## Why

The core feature of the brief (the `/ask` equivalent, see `docs/api-schema.md`'s mapping table) and
decisions 6 and 7 (answers as stored records; feedback kept).

## Design

`apps/api/src/services/answers.ts`, `AnswerService.ask`:

1. Run `rw-retrieve` and resolve hits to `ready` documents (`resolveHits`, shared with search).
2. No hit at or above `minScore` → store an ungrounded answer with the fixed text; no model call.
3. Otherwise run `rw-answer` with search tweaks plus `Prompt` (system prompt) and `LLM` (provider, model,
   base URL, key from `chatEndpoint` in `services/providers.ts`); the flow searches again with the same
   settings.
4. Parse text and citations (`rank` = the `[n]` in the text), token usage (`messageUsage()` in
   `@rag/langflow-client`), latency; store the row.
5. Failures: store `status: failed` with Langflow's message, a provider-key message, or "Something went
   wrong while answering."; return 502, 503 or 504 as in passage search. An empty model reply is a
   failure (502).

Access (`canSee`): only the asker (person or key) and admins can read or rate an answer; others get 404.

## Decisions and trade-offs

| Decision | Alternatives considered | Why this one |
| --- | --- | --- |
| Two flow runs: retrieve, then answer | One flow with a branch | Easier to read in Langflow and test; costs one extra query embedding |
| Citations stored as a snapshot | Look up live | Reindexing later doesn't change old answers |
| Store failures | Store only successes | Usage and analytics see them |
| Answers private to the asker and admins | Visible to the workspace | Owner confirmed 2026-11-20 |
| Zero token counts stored as null | Store zeros | LM Studio often reports none; null means unknown |
| Default system prompt: only from passages, cite `[n]`, say when not covered, answer in the question's language | No default | A workspace `systemPrompt` replaces it |

## Interfaces and contracts

- **HTTP API**:
  - `POST /v1/workspaces/{slug}/answers` (reader) `{ question, maxPassages? }` → 201 with `id`,
    `text`, `status`, `grounded`, `citations` (`rank`, `passageId`, `documentId`, `documentTitle`,
    `page`, `snippet`, `score`), `provider`, `model`, `usage` (`promptTokens`, `completionTokens`),
    `latencyMs`, `error`, `feedback`;
  - `GET /v1/workspaces/{slug}/answers/{answerId}`;
  - `POST .../answers/{answerId}/feedback` `{ rating: 'up' | 'down', comment? }` (rating again replaces).
- **Configuration**: `DEFAULT_CHAT_PROVIDER` (lmstudio), `DEFAULT_CHAT_MODEL` (qwen2.5-7b-instruct),
  `ANSWER_TIMEOUT_MS` (3 min), optional `ANTHROPIC_API_KEY` (chat only).
- **Data**: migration `0004_answers.sql`: table `answers` (asker kind and id, question, text, status,
  grounded, citations jsonb, provider, model, token counts, latency, time to first token, error, request
  id, feedback rating/comment/time) and enums `answer_status`, `caller_kind`, `feedback_rating`.
- **Langflow**: `rw-answer`: `Embeddings` and `Search` as in `rw-retrieve`, plus `Prompt` (`template`)
  and `LLM` (`provider`, `model_name`, `api_key`, `base_url`, `temperature`, `system_message`); outputs
  `ChatOutput-answer` (text) and `ChatOutput-citations`.
- **Events and logs**: internal error text is logged, never stored or returned.

## Operations

Rolling back the migration means dropping the table and enums; nothing existing changes.

## Testing

`apps/api/src/routes/answers.test.ts`: grounded and ungrounded paths, not-ready hits make it ungrounded,
empty model reply, failures stored, feedback by another user 404, a key and a person with the same id
don't see each other's answers, workspace scoping. Live with the stand-in model: grounded answer citing
page 1 in 378 ms; off-topic question ungrounded with no model call.
