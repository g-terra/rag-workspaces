# Passage search, one passage with its neighbours, a document's passages

## Summary

Callers can search a workspace's material without an AI answer, open one passage with the passage
before and after it, and page through a document's passages in reading order. Search runs the
`rw-retrieve` flow; reads by id go straight to Chroma. First piece of M2; answers reuse the same search
settings and error mapping.

## Why

The API schema's passages resource and decision 20 (Chroma through custom components; similarity search
needs the embedding model, so it stays in Langflow).

## Design

1. `apps/api/src/services/passages.ts`:
   - passage id conversion: `doc_X:3` in Chroma ↔ `psg_X_3` in the API;
   - `searchTweaks`: request value, else workspace setting, else global default;
   - `retrieve`: runs `rw-retrieve`, parses its fenced JSON;
   - hits from documents that are missing or not `ready` are dropped.
2. `apps/api/src/services/chroma.ts`: `getChunks` (read by id); shared collection-id lookup.
3. `apps/api/src/services/flow-errors.ts`: maps flow failures to HTTP (see Interfaces). `HttpProblem`
   gains optional headers.
4. `apps/api/src/routes/passages.ts`: the three routes.

## Decisions and trade-offs

| Decision | Alternatives considered | Why this one |
| --- | --- | --- |
| Search via Langflow, by-id reads direct from Chroma | Everything via Langflow | By-id needs no model: faster, works with LM Studio off |
| Deterministic passage ids from document and chunk index | Store passages in Postgres | No second copy of text; trade-off: changing chunk size changes what an old id points to |
| `minScore` default 0.3 | Higher or none | Tuned on the samples; overridable per workspace and per request |
| Drop hits whose document isn't `ready` | Show them | Mid-reindex or failed leftovers must not appear |

## Interfaces and contracts

- **HTTP API** (reader):
  - `GET /v1/workspaces/{slug}/passages?query=&limit=&minScore=`: scored passages, best first;
  - `GET /v1/workspaces/{slug}/passages/{passageId}`: the passage with its neighbours;
  - `GET /v1/workspaces/{slug}/documents/{documentId}/passages?limit=&cursor=`: paginated.

  Errors: Langflow without a key yet → 503 + `Retry-After: 10`; unreachable (`fetch failed`) → 503;
  missing provider key → 503; timeout → 504; flow failed → 502 with Langflow's reason.
- **Configuration**: `DEFAULT_TOP_K` (5), `DEFAULT_MIN_SCORE` (0.3), `RETRIEVE_TIMEOUT_MS` (30 s).
- **Data**: passage id format `psg_<document ulid>_<chunk index>`.
- **Langflow**: `rw-retrieve`: query in `input_value`; tweaks `Embeddings` (`model`, `base_url`) and
  `Search` (`collection_name`, `top_k`, `min_score`); output `ChatOutput-passages` as fenced JSON
  `{ collection, query, passages: [{ rank, id, text, score, document_id, filename, page, chunk_index }] }`.
- **Events and logs**: None.

## Operations

Passage ids are stable only while chunk settings stay the same.

## Testing

`apps/api/src/services/passages.test.ts` (no DB: id conversion, tweak precedence, parsing) and
`apps/api/src/routes/passages.test.ts` (fake Langflow and Chroma, real Postgres: not-ready hits dropped,
workspace scoping, stranger 404, anonymous 401, error mapping). Checked on the live stack.

## Out of scope and follow-ups

`folderId` and `startSeconds` on passages (folders, audio); 503 while a workspace reindexes.
