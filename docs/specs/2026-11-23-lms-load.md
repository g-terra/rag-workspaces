# Keep both LM Studio models loaded

## Summary

`docs/setup.md` now explains that LM Studio, loading models on demand, keeps only the last one by default,
so every question swaps the embedding and chat models. It shows how to load both with `lms load` so they
stay loaded. The setup wizard (`pnpm run setup`) offers to run those commands when the default chat or
embedding model is served by LM Studio and `lms` is installed. Otherwise, or with `--yes`, it prints them.

## Why

The answer-quality tuning on Guilherme's Mac (2026-11-23) found that LM Studio's
`unloadPreviousJITModelOnLoad` (on by default) unloads the previous just-in-time model whenever another is
requested. Each question embeds the query and then calls the chat model, so the two swapped every time, at
about 5 seconds each way. Models loaded with `lms load` are not just-in-time models and stay loaded.

## Design

1. `lmStudioModelsToLoad(env)` in `scripts/setup/choices.ts` returns the default chat and embedding
   model ids whose provider is `lmstudio`, chat first, with no duplicates.
2. `loadLocalModels` in `scripts/setup.ts` runs after `.env` is written. With no models it does nothing.
   Without `lms` on the PATH, or with `--yes`, it prints the `lms load` commands. Otherwise it asks (default
   yes) and runs `lms load <id>` for each, warning with what to do if one fails.
3. `docs/setup.md`, LM Studio section: the explanation and the two commands.

## Decisions and trade-offs

| Decision | Alternatives considered | Why this one |
| -------- | ----------------------- | ------------ |
| Load the models with `lms load` | Tell people to turn off `unloadPreviousJITModelOnLoad` | Loading is one command per model and needs no trip into LM Studio's settings. The docs name the setting for anyone who prefers that. |
| Ask before loading, and never in `--yes` | Load without asking | Loading a large chat model takes memory and time on the person's machine. That's worth a yes. |
| Use the ids from `.env` | Ask for LM Studio's model keys | LM Studio's API ids and its model keys match for downloaded models. If one doesn't load, the warning points to `lms ls`. |

## Interfaces and contracts

- **HTTP API**: None.
- **Configuration**: None.
- **Data**: None.
- **Langflow**: None.
- **Events and logs**: None.

## Operations

Run `pnpm run setup` again, or the two `lms load` commands, after LM Studio starts.

## Testing

- `scripts/setup/choices.test.ts`: both local models, chat first; a hosted chat model left out; nothing
  when neither is local.
- By hand, driving the wizard in a terminal: without `lms` it prints the commands, and with a stand-in
  `lms` on the PATH it asks, then runs `lms version`, `lms load <chat>` and `lms load <embedding>`.

## Out of scope and follow-ups

- Loading the models when the stack starts (`docker compose up`): `lms` runs on the host, not in a
  container.
